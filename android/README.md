# IdleArc Guide для Android

Неофициальная оболочка: вкладка **Игра** открывает оригинальный `https://idlearc.com/` в Android WebView; **Справочник** содержит офлайн-копию `hub/companion` (включается в APK при сборке); **Логи** показывают события текущего сеанса; **Анализ** показывает только распознанные числовые показатели с текущей открытой страницы игры. Для игры нужен интернет и Android System WebView. Для справочника интернет не нужен.

## Сборка и установка

Требуются JDK 17, Android SDK (platforms;android-35 и build-tools), Gradle 8.10.2. Из папки `android`:

```sh
gradle :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Или запустите workflow **Android APK** в GitHub Actions и скачайте артефакт `IdleArc-Guide-debug-apk`. Debug APK подписывается стандартным тестовым ключом; **не публикуйте его как релиз**. Для распространения нужен собственный release keystore и подпись.

## Границы анализа и безопасность

Это не модификация игры: приложению не доступны серверные данные, внутренние запросы приложения/игры, чужие вкладки или APK игры. Анализатор раз в 5 секунд берёт **только указанные числовые поля** из видимого текста DOM открытой страницы в WebView; он не читает пароли, cookie или содержимое сетевого трафика, не отправляет снимки и не ведёт историю. Набор полей и регулярные выражения — `Probe.java`; в зависимости от UI сайта показатели могут не обнаружиться или быть неточными. Код не автоматизирует нажатия, игру и авторизацию. HTTPS-страницы входа и всплывающие окна теперь открываются внутри приложения (адрес домена показывается в шапке); небезопасные HTTP-переходы блокируются. Исключение — вход Google: его OAuth не разрешён во встроенных WebView, поэтому приложение предупреждает об ограничении вместо молчаливого перехода в браузер. Для входа Google с возвратом сессии в APK нужна официальная поддержка IdleArc: мобильный OAuth redirect/App Link или обмен авторизационного кода на игровую сессию через их сервер, системный браузер / Custom Tabs и PKCE. Без этого ни внешний браузер, ни подмена User-Agent не перенесут автоматически Google-сессию в WebView. Справочник — снимок данных из репозитория, а не живые данные аккаунта. Используйте только в соответствии с правилами IdleArc.

## Иконка и пассивное дерево

Иконка APK сделана из `hub/brand/logo.png` с надписью «ГАЙД» поверх. Для повторной генерации размеров требуется Pillow: `python3 scripts/make-android-icon.py`. В справочнике каждый 10-й этаж теперь позволяет выбрать ровно **один из трёх** узлов: планировщик, ручной выбор и импорт/старые сохранения соблюдают это ограничение. Проверка: `node tests/companion-passive.mjs`.

## Обновления из GitHub (↻ APK)

Начиная с **v0.7.0** кнопка читает `update.json` из публичного GitHub Release (без GitHub API и токена), сравнивает версию, загружает APK, сверяет SHA-256 и подпись с уже установленным приложением и передаёт системному установщику после подтверждения. Если сервер релизных файлов отвечает 403/404, приложение пытается получить версию из перенаправления публичной страницы `/releases/latest`, а APK проверяет по подписи и идентификатору пакета. Если сам файл недоступен с телефона, выводится объяснение и его можно установить вручную с GitHub. Фоновая установка без подтверждения невозможна. **Версия 0.6.0 ещё использует GitHub API и при его 403 не сможет обновить сама себя**: установите 0.7.0 один раз вручную поверх подписанной 0.6.0, не удаляя приложение. Причина конкретного 403 на вашем устройстве без ответа сервера неизвестна.

Для публикации **подписанного** APK нужен только **один** секрет репозитория Actions: `ANDROID_SIGNING_SEED` — ровно 64 символа из `0-9a-f` (256 случайных бит). Он не записывается в APK или в репозиторий. Скрипт `scripts/derive-android-keystore.py` строит из него один и тот же приватный P-256 ключ, проверяет его соответствие публичному сертификату `android/signing-public.pem` и создаёт временный PKCS12 на раннере; пароль генерируется автоматически. **Не заменяйте этот секрет после первого релиза** — иначе обновления не пройдут проверку подписи. Сохраните резервную копию секрета вне GitHub. Старые четыре `ANDROID_KEYSTORE_*` и `ANDROID_KEY_ALIAS` теперь не используются и их можно удалить в настройках GitHub. После добавления одного секрета запустите workflow **Android APK** на текущей ветке вручную (workflow_dispatch) либо попросите запустить публикацию с маркером `[publish signed apk]` в коммите; после слияния ветки в main доступен также workflow **Publish signed Android release**. Для следующего релиза увеличьте `versionCode` и `versionName` в `app/build.gradle`. Нужны права Actions `contents: write` и разрешение создавать релизы.

**Важно:** предыдущие тестовые debug APK из CI подписаны другим временным ключом. Android не установит подписанный релиз поверх них. Перед переходом на подписанный APK сохраните важные данные справочника вручную, удалите debug-версию и установите первый подписанный релиз; далее OTA будет работать без удаления приложения. Никаких GitHub токенов или секретов в приложение не встраивайте.

Перед первой подписанной публикацией CI сверяет секрет `ANDROID_SIGNING_SEED` с публичным сертификатом. При несовпадении публикация прерывается без выпуска APK.

## Игровой журнал (версия 0.7.0)

Вкладка **Логи** теперь предназначена **только для событий игры**. Переходы по вкладкам APK («Игра», «Справка», «Анализ», «Логи»), проверка обновлений, открытие окон входа, вспомогательные действия интерфейса и загрузка картинок/скриптов **не попадают** в журнал. Там остаются:

- нажатия по кнопкам/ссылкам самой страницы IdleArc: известные английские названия переводятся на русский (например, `Inventory` → «Инвентарь», `Battle` → «Бой»); незнакомые названия остаются как на сайте, без выдуманного перевода;
- игровой обмен с доменом `idlearc.com` и его поддоменами: статус `fetch`/`XMLHttpRequest` и сообщения WebSocket без сырых тел. Если доступен читаемый JSON с предметами, **отдельная строка** перечисляет реальные поля не более трёх предметов (название, редкость, количество, уровень, атака, защита, здоровье), отдельно для запроса и ответа; например: «В ответе игры указаны предметы (1): Железный меч, редкость: редкая, количество: 2, атака: 14». Остальные поля не сохраняются;
- ошибки соединения **с игрой**. Чужие домены и авторизационные маршруты исключены.

Пример: «Вы нажали: кнопка „Инвентарь“ №7» → «Игра получила данные: предметы персонажа — успешно (код 200) · после действия №7 (по времени)». Связь по номеру — только **временная близость (1,5 секунды)**, а не доказательство, что именно это нажатие вызвало запрос. Неизвестные API-пути помечаются «игровые данные (раздел не распознан)»: приложение не приписывает им несуществующий смысл. Если интерфейс сайта нарисован в canvas, определить имя нарисованной кнопки без поддержки самой игры нельзя.

Журнал хранится только в RAM текущего запуска: максимум 300 записей, на экране последние 120. Сетевые события ограничены 12 строками/с, но суммарный счётчик продолжает расти. Кнопки «Пауза», «Очистить», «Копия» работают только с этим журналом. Нет токенов, query/fragment, почты, введённого текста, паролей, cookie, **полных** тел запросов/ответов и трафика других приложений. Для JSON читаются до 16 КБ и через мост передаются только разрешённые поля предметов (не более 3); при отсутствии понятного JSON/нужных полей, при бинарном/WebSocket-протоколе без JSON, либо если игра работает вне главного фрейма — нельзя достоверно показать состав предметов. Строка с кодом 200 подтверждает только успешный ответ, не состав инвентаря. Передавайте скопированные логи только добровольно. JS-мост AndroidX WebKit ограничен главным фреймом `https://idlearc.com` / `https://www.idlearc.com`, и вкладка сообщает, если WebView не поддерживает безопасный детальный режим. Это не VPN/прокси или гарантированная запись каждого серверного события.

Проверки: `node tests/android-game-probe.mjs`, `gradle -p android :app:testDebugUnitTest`, `node tests/companion-passive.mjs`, `node tests/smoke.mjs` (в CI запускаются перед выпуском APK). Проверка на телефоне: нажмите игровую кнопку, затем откройте «Логи» — переход на эту вкладку не должен появиться среди событий. Если кнопка неизвестна, пришлите её подпись/скриншот без личных данных для добавления перевода.
