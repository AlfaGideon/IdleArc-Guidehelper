# IdleArc Guide Helper

Веб-приложение (SPA без зависимостей), которое помогает **правильно собрать персонажа в IdleArc** — под класс, уровень и цель игры. Все данные — снапшот официальных источников: сайт игры `idlearc.com` (включая официальные патч-ноты 1.3.1 «Season 2: The Forge» и страницу классов) и открытая IdleArc Wiki.

> Это неофициальный фанатский инструмент. Он не подключается к аккаунту игры, не автоматизирует геймплей и не требует логина.

## Что умеет

- **Планировщик-гайд из 6 шагов.** Идёте сверху вниз: класс и цель → уровни → очки навыков → предметы → камни → чек-лист «что делать прямо сейчас». Внутри каждого шага — объяснение, почему именно так. Уровень персонажа и **Monster Level (ML) — два независимых параметра**: уровень даёт классовые очки, ML определяет, что падает и что доступно (тир предметов, диапазон имплиситов, редкость гемов, сокеты, открытие слотов, Torch с ML 50, двуручное оружие с ML 25). Все подписи в формате «Русское (English)» — понятно по-русски, а игровое название рядом для поиска в игре. Приложение:
  - **распределяет классовые очки по всем трём веткам** с учётом правил игры (1 очко на 1 уровне + 1 каждые 3 уровня; Tier 2 — после 5 очков в ветке, Tier 3 — после 10; требования между навыками). Доли ветвей зависят от цели: минимум 1 очко в каждую, остальное — пропорционально весам цели, затем сильные ветки «доводятся» до Tier 2/3. Одинаковых планов на разные цели не бывает, и для каждой ветки есть объяснение «почему столько очков»;
  - **учитывает +All Class Skills** (Torch, Sage Diadem, легендарные петы) отдельной панелью: ползунок 0…25, таблица прироста по каждому стат-эффекту и предупреждение там, где сработал кап навыка. Эффективный ранг = вложенные очки + бонус, и он виден у каждого навыка в дереве (гейты ветвей при этом считаются только по вложенным очкам);
  - даёт **ручной режим**: кнопки «+»/«−» у каждого навыка мгновенно пересчитывают бонусы, а валидатор подсвечивает превышение максимума, превышение доступных очков, закрытые тиры и невыполненные требования;
  - показывает итоговые бонусы (AD%, крит, Double Hit/Damage, пет, фарм-статы) и предупреждения (например, что данные Druid официально не описаны);
  - в шаге 4 показывает «скелет персонажа» — 10 слотов как в окне персонажа, где для каждого слота видно: русское (английское) имя семейства, имя предмета для вашего ML, имплисит текущего тира и полную лестницу T1→T6, аффиксы, Drop Bonus-ы и камень;
  - в шаге 6 выдаёт чек-лист под ваш уровень, ML и цель (например: «ML 50 — появится Torch, ставьте его обязательно»);
  - выдаёт **отдельный блок «Экипировка»**: сверху «скелет персонажа» — те же 10 слотов, что в окне персонажа в игре (основная рука, вторая рука, факел, нагрудник, шлем, перчатки, обувь, амулет, кольцо, пояс), с именем предмета и его имплиситом, ниже — подробная таблица по каждому слоту: семейство, имплисит (и его диапазон по тирам), до 4 рекомендованных аффиксов (только совместимые с семейством), целевые Drop Bonuses и гем, плюс пометка, если слот занят двуручным оружием;
  - выдаёт **отдельный блок «Гемы: какой камень куда ставить»**: памятка «лучшие камни под цель», затем по каждой слот-группе (оружие / факел / броня / украшения) — какой камень ставить в конкретный слот, что он там даёт, какую редкость брать на текущем уровне и какие есть альтернативы в этом слоте; ниже — когда менять основной камень, таблица вторичных статов с отметкой приоритета и порядок работы с сокетами;
  - выдаёт приоритет характеристик, талисманы и состав петов;
  - экспортирует план текстом (для Discord) и кодом сборки, который можно передать другому игроку.
- **Пассивное дерево (Passive Skill Tree).** Отдельная вкладка с рекомендациями по прокачке общего пассивного дерева под класс, цель и уровень: дерево — 20 тиров по 10 рядов (все 200 рядов — снапшот данных текущего билда игры), 1 пассивное очко за уровень, следующий тир открывается после 20 очков в предыдущем. Приложение само раскладывает очки «вглубь» (20 на тир — глубокие узлы в разы сильнее), выбирает в каждом ряду узел под цель (урон атаки / урон пета / крит / защита / фарм), подбирает майлстоуны (каждый 10-й ряд — мощные узлы по 1 очку) и показывает итоговые бонусы. Приоритеты согласованы с остальным планировщиком (те же правила целей), класс/цель/уровень подхватываются из планировщика.
- **Калькуляторы.** Урон (крит >100% → Crit Damage, «полные сотни» Double Hit/Double Damage, Boss Damage, Shadow Echo), защита (софт-кап DR 95% / хард-кап 99%, минимум 1% урона), Retaliation (`Reflecting% × Defense`, блок +50%), значение гема, стоимость Mastery, компоунд петов, классовые очки.
- **Кодекс.** Поиск и фильтры по классу и слоту; каталог всех 40 семейств из Item Codex (имена по тирам T1→T6/A1, имплисит по тирам, совместимые аффиксы, условие выпадения) + аффиксы, Drop Bonuses (T2→T9), гемы и сокеты, классовые навыки, талисманы и инскрипты, петы, статы и стойки, Mastery, ML-анлоки, биомы, Convergence, гильдия, смена класса.
- **Нюансы и источники.** Список ловушек билдостроения (капы, диминишинг Lucky, баланс компоунда петов, `Slayer's` только для боссов и т.д.) + список источников и явная маркировка «подтверждено / требует проверки».

## Запуск

**Windows — двойной клик по `start.bat`.** Запускается **хаб «две стороны»** (порт **8080**): Guide Helper и Companion в одной оболочке, клик по логотипу в шапке переворачивает стороны. Этот файл сам:

- находит Node.js (в `PATH` или в `C:\Program Files\nodejs`), а если его нет — объясняет, что скачать, и предлагает открыть страницу установки;
- выбирает свободный порт: по умолчанию **8080** (хаб), а если он занят (например, другой программой) — следующий свободный; можно задать свой: `start.bat 8090`;
- умеет и классический запуск: `start.bat arc` — только Guide Helper (`server.js`, порт 5173), как было до появления хаба;
- поднимает сервер и открывает приложение в браузере **только после того, как сервер реально ответил** — вместо «не удаётся подключиться» из-за слишком раннего запуска;
- если приложение уже запущено в другом окне, второй сервер не поднимает — просто открывает браузер (двойной клик по `start.bat` ничего не ломает);
- слушает только `127.0.0.1`, поэтому Windows не показывает запрос файрвола.

Остановка — `Ctrl+C` в окне запуска или просто закрыть окно. Нужен Node.js 18 или новее (<https://nodejs.org/>); само приложение ставить никуда не нужно, оно запускается прямо из папки проекта.

**Любая ОС — та же логика из терминала** (на Linux/macOS `start.bat` не нужен):

```bash
node scripts/serve.mjs             # хаб «две стороны» (8080): свободный порт + открыть браузер
node scripts/serve.mjs 8090        # хаб на конкретном порту
node scripts/serve.mjs --arc       # только Guide Helper (5173), без хаба
node scripts/serve.mjs --no-open   # не открывать браузер (удобно для тестов)
node scripts/serve.mjs --lan       # доступ с других устройств в локальной сети
```

**Самый простой вариант** — только сервер Guide Helper, порт задаётся вручную:

```bash
node server.js            # http://localhost:5173  (PORT=8080 node server.js — другой порт)
node hub/hub-server.js    # хаб «две стороны»: http://localhost:8080
```

Сервер без зависимостей (только Node.js ≥ 18). Приложение — статика, поэтому подойдёт любой статический хостинг (GitHub Pages, Netlify, `python3 -m http.server`).

## Тесты

```bash
node tests/smoke.mjs      # логика, данные, рендер в строгом DOM-шиме
node tests/http.mjs       # интеграция: сервер отдаёт граф модулей как браузеру
```

HTTP-тесту нужен запущенный сервер Guide Helper (сторона A, не хаб): сначала `start.bat arc` (Windows) или `node scripts/serve.mjs --arc --no-open`, затем во втором окне `node tests/http.mjs`. Порт берётся из `PORT` (по умолчанию 5173) — если лаунчер выбрал другой порт, укажите его: `PORT=5174 node tests/http.mjs` (в Windows: `set PORT=5174` перед запуском).

Обновление в браузере (важно, если вы уже открывали приложение):

- сервер отдаёт все файлы с `Cache-Control: no-store` и **версионированными путями**: `index.html` подставляется как `/v/<сборка>/src/app.js`, поэтому у каждого релиза свои адреса модулей и смешать старые и новые файлы браузер не может;
- метка сборки видна в шапке и подвале, её же отдаёт `/api/build`;
- если модули не загрузились (кэш, прокси, старый браузер), страница больше не остаётся пустой: сверху появляется красный блок с текстом ошибки, метками сборок и кнопкой «Перезагрузить» — пришлите текст из него, если что-то не так;
- при изменении данных поднимите `DATA_META.build` в `src/data/systems.js` и `<meta name="build">` в `index.html` (совпадение проверяется тестом).

Смоук-тест прогоняет рендер всех вкладок через лёгкий DOM-шим и проверяет: планировщик по 5 классам × 5 целям × 5 уровням, использование всех трёх ветвей, отличие планов разных целей, работу +All Class Skills (прирост бонусов и непревышение капов), непрохождение Tier-гейтов от +All, валидацию ручного режима, план экипировки и гемов (10 слотов, соответствие семейству/статам цели), целостность каталога предметов, коды сборок и формулы (крит >100%, DR-капы, Retaliation, гемы, компоунд петов, Mastery), а также локальный запуск — `start.bat` и `scripts/serve.mjs` (CRLF-переводы строк, отсутствие BOM, латиница в командах).

## Откуда цифры: данные игры без «выдуманных» значений

- **Официальные параметры игры:** правила очков и тиров, ветки/тиры/максимальные ранги и значения всех 90 классовых навыков (включая Druid — Lodge / Tunnels / Symbiosis), аффиксы и их роллы, Drop Bonuses T2–T9 (со шкалами по тирам), гемы (формула и таблицы), петы (шансы, pity, капы компоунда), талисманы, Mastery, ML-анлоки, Convergence, Guild Skill Tree, изменения патча 1.3.1.
- **Классовые навыки:** каждый навык в `src/data/classes.js` содержит `branch`, `tier` и настоящий `max` (5 или 10 очков) из текущего билда, значение за очко (`perPoint`), предел эффекта (`cap`) и предусловие (`requires`), если оно есть. Таблица в шаге 3 сгруппирована по тирам, поэтому видно, какой навык к какому тиру относится и сколько очков в него можно вложить.
- **Проверка автоматическая:** `node tests/smoke.mjs` сверяет все 90 навыков с эталонной таблицей (ветка, тир, макс. ранг) — если игра изменит дерево, тест упадёт раньше пользователя.
- **Модель, а не официальная формула:** расчёт ожидаемого множителя удара (крит >100%, «полные сотни» DH/DD, капы DR). Порядок слоёв урона игра не раскрывает, поэтому цифры годятся для сравнения вариантов, но не как точный DPS.
- **Как обновлять данные:** см. раздел «Как обновлять данные» в `docs/RESEARCH.md` — правки делаются в `src/data/*.js`, после них поднимается метка сборки (`DATA_META.build` и `<meta name="build">`) и прогоняются оба теста.

## Хаб: две стороны одной монеты

`hub/` — оболочка, которая объединяет два независимых приложения. Клик по логотипу
в шапке переворачивает «монету» между ними (есть и сегмент-переключатель, и `Alt+Tab`).

* **Сторона A — IdleArc Guide Helper** — этот проект, как есть (корень репозитория).
* **Сторона B — IdleArc Companion** — полная офлайн-копия
  `idlearc-companion-web` в `hub/companion/` с новой вкладкой **«Пассивка»**.

Именно этот хаб теперь запускается двойным кликом по `start.bat` (или вручную):

```bash
node hub/hub-server.js      # http://localhost:8080
```

Хаб сам поднимает `server.js` из корня репозитория на `127.0.0.1:5173` и проксирует
на него `/arc/*` (и `/api/*`), поэтому `/api/build`, `/api/art/status`,
`/api/art/fetch` и `/api/art/upload` продолжают работать. При этом хаб устойчив
к конфликтам: если 5173 уже занят нашим сервером (открыто старое окно `start.bat`),
хаб переиспользует его, а не плодит копию; если порт занят чужой программой — сторона A
поднимется на следующем свободном; если сторона A упала (закрыли то старое окно) —
хаб перезапустит её при следующем обращении. Порт самого хаба тоже подбирается
автоматически (8080, занят — следующий свободный), а `HOST=0.0.0.0 node hub/hub-server.js`
открывает доступ по локальной сети.

### Вкладка «Пассивка» (сторона B)

* 5 классов × 5 профилей прокачки: Баланс / Боссы / Фарм-лут / Танк / Петы.
* Генератор плана на N очков идёт **этаж за этажом сверху вниз**, добивает тир
  до порога в 20 очков и только потом открывает следующий.
* Правила дерева, которые нельзя нарушить кликами:
  * этаж открывается, только если на предыдущем есть ≥ 1 очко — **перескок невозможен**;
  * тир открывается только при наборе порога очков в предыдущем тире;
  * нельзя снять очко, если на нём держатся этажи ниже.
* Рекомендации текстом по каждому классу, топ-8 приоритетных статов,
  «следующие 8 шагов» и кнопка «Применить план» (пишет раскладку в Build Studio).
* Переключатель языка RU/EN.
